# COVID-19 reported cases and deaths

**Research question:** Do cases reported two weeks earlier improve prediction of a state's weekly reported death rate beyond its previous week's death rate?

This independent R Markdown analysis covers the 50 U.S. states and Washington, D.C. It fits models on April 2020–December 2021 and evaluates frozen models on 2022. It compares persistence, a state-intercept death-history regression, and the same regression with lagged cases. Five figures, paired moving-block resampling, a negative-correction sensitivity analysis, conclusions, and bias discussion are included.

This is a retrospective final-vintage exercise, **not** a real-time backtest or a causal analysis. No claim is made that a model must outperform persistence. Course-example code was not supplied; the analysis was designed independently, so exact overlap with lectures cannot be verified.

## Reproduce

1. Install R (tested with R 4.5.2). RStudio is convenient and includes Pandoc. Without RStudio, install Pandoc separately and make it discoverable on PATH or via `RSTUDIO_PANDOC`.
2. Install packages once:

   ```r
   install.packages(c("rmarkdown", "knitr", "ggplot2"),
                    repos = "https://cloud.r-project.org")
   ```

3. Download the repository ZIP and unzip it, or download this whole folder.
4. Open `covid19_cases_and_deaths.Rmd` in RStudio and click **Knit**. Alternatively, start in this folder and run:

   ```r
   rmarkdown::render("covid19_cases_and_deaths.Rmd")
   ```

   Or use `Rscript --vanilla path/to/render_report.R` from any directory.

No local absolute paths are embedded in the analysis. With raw data present, rendering does not need network access. Downloading just the Rmd also works with network access: it creates `data/raw`, downloads both pinned CSV files, and checks them before analysis. Package installation is intentionally separate from knitting. Runtime is typically under a few minutes, depending on hardware.

Validated on 2026-10-08 with R 4.5.2, rmarkdown 2.32, knitr 1.52, ggplot2 4.0.3, and Pandoc 3.12.1. A fresh `Rscript --vanilla` run in a separate folder reproduced all six result tables exactly. Independent numerical checks reproduced the weekly rates, calendar lags, regression predictions, MAE, and RMSE. The report prints its actual runtime package versions and session details. Only the benign Windows package-binary R patch-version notice is filtered during package loading; analysis warnings remain enabled.

## Analysis choices

- State totals include all county-like records assigned to the state, including unassigned/out-of-state records. Territories and ships are excluded.
- The JHU death file supplies the fixed population denominator.
- Sunday cumulative totals are differenced into Monday–Sunday net weekly reports. Lagging occurs on a complete calendar before exclusions.
- Negative counts become missing in the primary analysis. Zero-clipping is a separately reported sensitivity analysis, not a silent correction.
- Models and metrics weight each retained state-week equally.
- Predictions use previous observed test values, with fixed training coefficients. No target week's cases or deaths are used as predictors.
- Final-vintage revisions, publication delays, common waves, omitted factors, and ascertainment changes limit interpretation.
- Results, package versions, and `sessionInfo()` are generated by code, not typed in manually.
